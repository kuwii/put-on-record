# put-on-record（记录在案）

工作留痕：两个配套的 agent skill，一个负责**记录**，一个负责**整理**。

- **put-on-record（记录在案）**：把当前 session 相关的事情整理为客观、极简的 Markdown 文件，分两类：
  - **工作记录**（`record`）：**用户本人已完成的工作**（agent 做的事算用户做的），以用户第一人称"我"记录，供整理述职报告、在争端中举证、回溯事实等使用。
  - **任务记录**（`task`）：**用户本人被布置的工作任务/计划**（用户是任务承接人，记录中的"我"指用户），要求自包含，隔段时间只读该文件就能重新理解任务。

  两类记录都要求**自包含**：换台设备、只凭文件本身（加上其中的远程链接）也能读懂，不依赖本机文件。

- **tidy-on-record（整理在案）**：对已有的工作记录目录做归档整理——把根目录中扁平堆放的记录按任务或工作内容归入主题子目录，把同一项工作下高度相似的记录合并成一份并简化描述，同时维护索引。适合定期（每周/每两周）调用。

## put-on-record（记录在案）

- **触发**：用户说"记录在案"/"Put on record"，或要求工作记录、留存证据、争端留证、工作日志、述职素材等；或要求"记录任务"、"任务留痕"、"记录布置给我的任务"、工作任务/任务安排留痕等。未指明记录哪一类时由 skill 按 session 内容自动判断（有已完成工作记工作，刚布置的任务记任务）。
- **写到哪**：用户指定的 Markdown 文件；用户指定的目录（在目录根层生成 `YYYY-MM-DD-record-{x}-{work-content}.md` 或 `YYYY-MM-DD-task-{x}-{task-content}.md`，两类各自独立编号，子目录中的同日记录也计入编号）；或用户/项目上下文中明确指定给本 skill 的记录目录。都没有则拒绝执行并要求提供。
- **记什么**：
  - 工作记录：**这是用户本人的工作记录，以用户第一人称"我"写**——agent 做的事算用户做的，不写成"agent 为用户……"；只记已完成的事实（写了什么、跑了什么、调研了什么……），不记计划、未完成部分、推测；**自包含**：不写本地文件路径、不引用本机文件，工作内容用结果性描述、不列文件/命令清单（记录是纪要，抠细节可去翻 commit）；内容已上传云盘或 git 远端的记远程链接，git 已提交的记仓库名 + commit ID（有远端 commit/PR/MR 链接更好）。
  - 任务记录：**这也是用户本人的任务记录，以用户视角写**——任务主体是"我"，"布置人/来源"指把任务布置给用户的人/渠道，不写成"布置给 agent 的任务"；任务内容、背景、完成标准、截止时间等可知才写；**自包含**（不写本地文件路径、不引用本机文件和其他本地记录；本地文件要点内联，云盘/git 远端链接可保留，严禁写入密钥/token 等凭证）；写前审视当前上下文（AGENTS.md、项目文档、MCP 等）并内联相关事实。
  - 正文记录精确到分钟、带时区的时间；一次调用只产出一个文件。
- **合并**：目录下发现高度相似的同类既有记录（task 只和 task 比；含主题子目录中的记录）时先询问用户是否合并；合并后全文改写为一次成文的风格，时间部分不变。

## tidy-on-record（整理在案）

- **触发**：用户说"整理在案"、"整理工作记录"、"整理记录目录"、"归档工作记录"、"合并同类工作记录"、"给工作记录建索引/重建索引"、"清理整理回收站"，或要求定期整理、归档、合并已有工作记录时。
- **整理后的结构**：

  ```text
  <记录根目录>/
  ├── INDEX.md                 # 总索引（主题导航 + 统计）
  ├── auth-refactor/           # 主题目录：一项工作 / 一个任务
  │   ├── INDEX.md             # 主题索引（文件、时间、摘要）
  │   └── 记录文件...
  ├── misc/                    # 归不进任何主题的兜底
  └── _trash/<时间戳>/          # 合并时移出的原件，可恢复
  ```

  `put-on-record` 始终把新记录写在根层（收件箱），由 tidy 归档进主题目录。
- **同类项合并**：只合并同类型、同主题、确属同一项工作且要点高度重叠的记录；合并后时间取覆盖区间、正文去重简化，**不删事实、不编造**；合并文件按 `YYYY-MM-DD~YYYY-MM-DD-record-{x}-{content}.md` 命名。拿不准的不合并，列为候选。
- **索引**：根 `INDEX.md`（主题导航、统计、用户整理的长期备注）+ 每主题 `INDEX.md`（时间/类型/文件/摘要）。索引即归档状态，每次整理先核对索引与文件系统、以文件系统为准修复漂移，重复运行安全；不引入额外的状态文件。
- **安全**：默认先出整理方案、用户确认后执行；定时任务可声明"直接执行"进入自动模式（当天新增只归档不合并、低置信不合并、绝不删除）；合并前原件移入 `_trash/`，不自动清理。
- **定期调用**：在 agent 工具的定时任务里配置，prompt 形如 `整理在案：整理 <记录根目录>，无人值守，直接执行，不用询问，结束后给出整理简报。`；示例见 [skills-cn/tidy-on-record/references/scheduling.md](skills-cn/tidy-on-record/references/scheduling.md)。

完整规则见 [skills-cn/put-on-record/SKILL.md](skills-cn/put-on-record/SKILL.md) 与 [skills-cn/tidy-on-record/SKILL.md](skills-cn/tidy-on-record/SKILL.md)。

## 安装

无安装脚本，请将对应 skill 目录复制或软链接到 agent 工具的 skills 目录：

```bash
# 以 pi coding agent 为例
ln -s "$PWD/skills-cn/put-on-record" ~/.pi/agent/skills/put-on-record
ln -s "$PWD/skills-cn/tidy-on-record" ~/.pi/agent/skills/tidy-on-record
# 或
cp -r skills-cn/put-on-record skills-cn/tidy-on-record ~/.pi/agent/skills/
```

两个 skill 可以单独安装；`put-on-record` 写入、`tidy-on-record` 整理，配合使用效果最好。其他 agent 工具（Claude Code、Codex 等）同理，放到各自的 skills 目录即可。

“记录在案”

面向“工作要留痕”的 agent skill

1 这是什么

这个项目包含两个配套的 agent skill：put-on-record（记录在案）负责记录，tidy-on-record（整理在案）负责整理。前者把当前 session 相关的事情整理成客观、极简的 Markdown 文件，作为日后的工作历史，分两类：

  • 工作记录（record）：把已经做过的工作总结成工作记录——这是用户本人的工作记录，以用户第一人称"我"来写（agent 做的事算用户做的），只记已发生的事实，不记计划与推测。
  • 任务记录（task）：把用户本人被布置的工作任务/计划（用户是任务承接人，记录中的"我"指用户）记成一份自包含的任务文件——隔段时间后，只读这个文件就能重新理解任务。

很多工作场景需要"留痕"：定期写述职报告，要能列出这段时间做过什么；工作中产生争端时，精确的工作记录是有利的证据；任务安排下来过了一阵子，也需要能完整回忆起任务的内容和背景。这个 skill 写出的记录可以直接作为这些场景的素材。记录又往往要长期保存、甚至放进云盘备份，所以它必须自包含：不引用写记录时那台电脑上的原文件，换台设备也能看懂。

怎么触发：对 agent 说"记录在案"或 "Put on record"，或者用自然语言要求做工作记录、留存证据、工作日志、述职素材等；记录任务则说"记录任务"、"任务留痕"、"记录布置给我的任务"等。没说记哪一类时，skill 会根据 session 内容自动判断（有已完成的工作记工作，刚领的活记任务）。

2 怎么用

调用时告诉它写到哪里：

  • 指定一个 Markdown 文件路径：记录写进那个文件；文件已存在时视为更新那份记录。
  • 指定一个目录：在目录中生成记录文件，文件名固定为 YYYY-MM-DD-record-{x}-{work-content}.md（工作记录）或 YYYY-MM-DD-task-{x}-{task-content}.md（任务记录）：日期精确到天，x 是从 1 开始的当日序号，两类各自独立编号（同日已有同类记录时取该类当前最大值 +1），内容词是几个英文单词 + 连字符的概括。例如 2025-11-03-record-1-fix-login-bug.md、2025-11-03-task-1-wiki-dark-mode.md。
  • 什么都没指定：如果用户或项目上下文中已经明确指定了用于本 skill 的记录目录，就用那个目录；否则拒绝执行，要求提供目录或文件路径。

3 记录什么

两类记录的规则：

工作记录：

  • 这是用户本人的工作记录：全文以用户第一人称"我"来写，agent 做的事算作用户做的事，不出现"agent/助手帮用户……""用户要求我……"这类表述。
  • 只记已完成的事实：改了哪些代码、写了什么文档、跑通了什么、调研了什么、提交或沟通了什么；不记未来计划、未完成部分、未查明的事实、推测。
  • 自包含，换台设备也能读懂：不写本地文件路径、不引用本机文件；工作内容用结果性描述，不列文件/命令清单；内容已上传云盘或 git 远端的记远程链接，git 已提交的记仓库名 + commit ID（有远端 commit/PR/MR 链接更好）。
  • 本 session 已经用过一次时，只记录上次记录之后的增量。

任务记录：

  • 这是用户本人的任务记录：以用户视角写（"我接到的任务"），不写成"布置给 agent 的任务"；"布置人/来源"指把任务布置给用户的人或渠道。
  • 只记任务本身：任务内容、背景、完成标准、截止时间、布置人/来源；可知才写，不编造。
  • 自包含：不写本地文件路径、不引用本机文件和其他本地记录；涉及本地文件时把要点内联进文件，不写"见 ./xxx"；云盘、git 远端等在线链接可以保留；严禁写入密钥、token、密码等凭证信息。
  • 写之前会审视当前上下文（AGENTS.md、项目文档、MCP 工具等），把与任务相关的事实内联补全背景；可以调用它们的只读能力查细节（如从日历确认截止时间），不做写操作。

两类通用：文风准确、极简、客观，不做任何修饰；正文记录精确到分钟、带时区的时间（上下文中已有相关时间区间或重要时刻时记那些；只有"今天下午"这类模糊时段或没有时间信息时，记本次写记录的时刻）；一次调用只产出一个文件。

如果目标目录里已有与本次内容高度相似的同类记录（task 只和 task 比，record 只和 record 比；已被整理进主题子目录的记录同样参与比较），skill 会停下来询问是否合并进那份既有记录。合并后会把整个文件改写成一次成文的样式（时间部分保持不变），并重新检查文件名中的内容概括是否仍然贴切。

4 整理与索引

长期使用后，记录目录会越来越扁平、越堆越多。配套的 tidy-on-record（整理在案） 负责定期整理：把根目录里扁平的记录按任务或工作内容归入主题子目录，把同一项工作下高度相似的记录合并成一份并简化描述，同时维护索引。

整理后的目录形如：

<记录根目录>/
├── INDEX.md                 # 总索引：主题导航 + 统计
├── auth-refactor/           # 主题目录：一项工作 / 一个任务
│   ├── INDEX.md             # 主题索引：时间、类型、文件、摘要
│   └── 记录文件...
├── misc/                    # 归不进任何主题的兜底
└── _trash/<时间戳>/          # 合并时移出的原件，可恢复

put-on-record 始终把新记录写在根层（收件箱），由 tidy 归档进主题目录。索引是两级 Markdown（根 + 每主题），人可直接读、agent 也能增量维护；索引即归档状态，每次整理先核对索引与文件系统、以文件系统为准修复漂移，重复运行安全。

合并只针对同类型、同主题、确属同一项工作且要点高度重叠的记录；合并后时间取覆盖区间、正文去重简化，不删事实、不编造。拿不准的不合并，列为候选。合并前的原件移入 _trash/，不会直接删除。

怎么触发：对 agent 说"整理在案"、"整理工作记录"、"归档工作记录"、"合并同类工作记录"、"给工作记录建索引"等。默认先给出整理方案、确认后执行；在定时任务的 prompt 里写"直接执行，不用询问"即可进入自动模式（当天新增只归档不合并、低置信不合并、绝不删除）。需要定期整理时，在 agent 工具的定时任务里配置：

整理在案：整理 <记录根目录>，无人值守，直接执行，不用询问，结束后给出整理简报。

5 安装

没有安装脚本。先把仓库克隆到本地，再把 skill 目录复制或软链接到你 agent 工具的 skills 目录：

# 1. 克隆仓库到本地
git clone https://github.com/kuwii/put-on-record.git

# 2. 以 pi coding agent 为例，软链接（或复制）两个 skill 目录
ln -s /path/to/put-on-record/skills-cn/put-on-record ~/.pi/agent/skills/put-on-record
ln -s /path/to/put-on-record/skills-cn/tidy-on-record ~/.pi/agent/skills/tidy-on-record

# 或者复制
cp -r /path/to/put-on-record/skills-cn/put-on-record /path/to/put-on-record/skills-cn/tidy-on-record ~/.pi/agent/skills/

两个 skill 可以单独安装；配合使用效果最好。其他 agent 工具（Claude Code、Codex 等）同理，放到各自的 skills 目录即可。如果不确定自己的 agent 工具的 skills 目录在哪里，直接问它一句就行。

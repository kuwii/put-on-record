“记录在案”

面向“工作要留痕”的 agent skill

1 这是什么

这个项目是一个 agent skill：put-on-record（记录在案）。它把当前 session 中已经做过的工作总结成一份客观、极简的 Markdown 记录文件，作为日后的工作历史。

很多工作场景需要"留痕"：定期写述职报告，要能列出这段时间做过什么；工作中产生争端时，精确的工作记录是有利的证据。这个 skill 写出的记录可以直接作为这些场景的素材。

怎么触发：对 agent 说"记录在案"或 "Put on record"，或者用自然语言要求做工作记录、留存证据、工作日志、述职素材等。

2 怎么用

调用时告诉它写到哪里：

  • 指定一个 Markdown 文件路径：记录写进那个文件；文件已存在时视为更新那份记录。
  • 指定一个目录：在目录中生成记录文件，文件名固定为 YYYY-MM-DD-record-{x}-{work-content}.md：日期精确到天，x 是从 1 开始的当日序号（同日已有记录时取当前最大值 +1），work-content 是几个英文单词 + 连字符的内容概括。例如 2025-11-03-record-1-fix-login-bug.md。
  • 什么都没指定：如果用户或项目上下文中已经明确指定了用于本 skill 的记录目录，就用那个目录；否则拒绝执行，要求提供目录或文件路径。

3 记录什么

记录的内容规则：

  • 只记已完成的事实：写了什么代码、写了什么文档、运行了什么命令、调研了什么、提交或沟通了什么。
  • 不记未来计划、未完成部分、未查明的事实、推测；不做任何修饰。
  • 正文记录精确到分钟、带时区的时间；上下文中已有工作时间区间或重要时刻时记那些，否则记录本次写记录的时刻。
  • 处于 git 仓库且改动已提交时，记录 commit ID。
  • 一次调用只产出一个文件；本 session 已经用过一次时，只记录上次记录之后的增量。

如果目标目录里已有与本次工作内容高度相似的记录，skill 会停下来询问是否合并进那份既有记录。合并后会把整个文件改写成一次成文的样式（时间部分保持不变），并重新检查文件名中的工作内容概括是否仍然贴切。

4 安装

没有安装脚本。把 skill 目录复制或软链接到你 agent 工具的 skills 目录即可：

# 以 pi coding agent 为例
ln -s /path/to/put-on-record/skills-cn/put-on-record ~/.pi/agent/skills/put-on-record

# 或者复制
cp -r /path/to/put-on-record/skills-cn/put-on-record ~/.pi/agent/skills/

其他 agent 工具（Claude Code、Codex 等）同理，放到各自的 skills 目录即可。

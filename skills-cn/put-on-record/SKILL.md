# Put on Record：工作留痕

把当前 session 中**已完成的工作**总结成一份 Markdown 工作记录文件，供日后整理述职报告、在争端中举证、回溯事实使用。**只记已发生的事实，不记计划与推测。**

## 第一步：确定写到哪里

按优先级判断：

1. **用户给了 Markdown 文件路径** → 写到那个文件。文件不存在 → 创建（必要时创建父目录）；文件已存在 → 视为**更新工作记录**，跳到"相似/相同记录合并"一节处理。
2. **用户给了目录** → 在该目录下按"文件命名"一节生成新文件（目录不存在则创建）；写入前先做"相似性检查"。
3. **两者都没给**，但用户或项目级别的上下文（如 AGENTS.md、项目说明文件）中**明确指定**了用于本 skill / 用于写工作记录的目录 → 按第 2 条使用那个目录。普通目录（如 `docs/`、`notes/`）不要误认为记录目录。
4. **否则** → 拒绝执行，请用户给出记录目录或目标文件路径。

## 第二步：相似性检查（仅当要新写文件时）

在目标目录中查找与本次要整理的工作内容**高度相似**的既有记录：先按文件名中的 `work-content` 描述词粗筛，再打开疑似候选文件读正文确认——描述词太短，不要只凭文件名判断（例如 `fix-login-bug` 和 `patch-auth-flow` 可能是同一件事）。

- 找到 ≥1 个相似文件 → **停下来询问用户**：列出每个候选（文件路径 + 一句话内容摘要），问是否合并进其中某个既有记录，还是写新文件。
- 用户选择合并进既有文件 → 按"相似/相同记录合并"一节处理；否则写新文件。

## 文件命名

```
YYYY-MM-DD-record-{x}-{work-content}.md
```

- `YYYY-MM-DD`：当天日期（四位数年份、两位数月份、两位数日期）。
- `{x}`：序号，**恒有**。在目标目录中查找当天日期的所有 `YYYY-MM-DD-record-{N}-*.md`（N 为数字）文件，取目前最大序号 +1；当天尚无记录则从 1 开始。
- `{work-content}`：高度概括的工作内容描述，几个英文单词 + 连字符（如 `fix-login-bug`、`investigate-k8s-networking`）。
- 若 session 里明显包含**多个互不相干的工作主题**，先问用户：只记录其中某个主题，还是笼统合记（合记时与用户确认 `work-content` 取什么词，可用 `misc` 之类的笼统词）。

## 记录什么

**只记录已完成的工作事实**：写了什么代码、写了什么文档、运行了什么命令、调研了什么、提交/汇报/沟通了什么，等等。

- 不记未来计划、未完成部分、未查明的事实、推测；也不写背景/动机/结论。
- 文风：准确、极简、客观，不做任何修饰。
- 默认范围是整个 session；**若本 session 之前已成功调用过本 skill**（回看 session 历史找到上次写入的记录文件），则只记录从那次记录之后到当前时刻的工作。若 session 历史中找不到此前的调用记录，则记录整个 session——若有重复，由相似记录合并规则兜底。
- 用户可以用额外说明缩小记录范围，以用户指示为准。
- 一次调用只产出/更新一个文件。

## 记录模板（极轻，允许自由发挥）

```markdown
# {工作一句话标题}

**时间**：{时间，见下}

**工作内容**：
- {客观事实 1}
- {客观事实 2}

**涉及文件/命令**：
- {文件路径 / 关键命令}
```

- **时间**：若 session 上下文中已有工作时间区间或重要时刻（如某改动提交于何时、某问题反馈于何时），记录下来（区间或若干时刻均可）；否则记录本次写记录的时刻。精确到分钟并带时区，如 `14:30 ~ 15:42 (UTC+8)` 或 `2025-11-03 15:42 (UTC+8)`。
- **涉及文件/命令**：列出相关的文件路径、关键命令；若处于 git 仓库且相应改动**已提交**，记下 commit ID。
- 记录正文语言跟随对话语言。
- 模板覆盖不到的场景（如争端场景需要详细陈述事件经过与时间点）按需调整；用户的额外说明优先。

## 相似/相同记录合并

适用于两种情况：用户直接指定了一个已存在的文件，或相似性检查后用户确认合并进某个既有文件。

1. 将本次工作内容并入该既有记录。
2. 将全文改写成一次成文的风格——成品看不出任何被更新过的痕迹。
3. **时间部分保持不变**。
4. 重新审查文件名中 `work-content` 部分是否仍能代表更新后的整体内容：不能则更新文件名（相应重命名文件）。文件名本就不符合上述命名规范的，不强行重命名。

## 完成后

向用户简报：记录已写入（新建还是更新）及文件路径。无需赘述。
